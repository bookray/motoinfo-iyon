## Спецификация 10 функциональных модулей

### Модуль 1. Режим тишины для системы репутации («Не выводить сообщения об изменении репутации»)

#### 1.1. Назначение
Обеспечивает фоновую работу рейтинговой системы в высокоактивных чатах: бот начисляет или списывает баллы, но **не отправляет ответные сообщения в группу** (`⭐️ Репутация повышена/снижена`), исключая спам и замусоривание публичной переписки.

#### 1.2. Требования к реализации
- Добавить флаг конфигурации `muteReputationChangeMessages: boolean` (по умолчанию `false`) в хранилище настроек (`settings` и `filters`).
- При изменении флага в веб-интерфейсе:
  - Если `muteReputationChangeMessages === true`, параметр `reputationNotifyInGroup` автоматически выставляется в `false`.
  - Изменение сохраняется моментально (auto-save) через `PUT /api/filters` и `PUT /api/settings`.
- В обработчиках событий бота:
  - Перед вызовом `ctx.reply(...)` проверять условие:
    ```typescript
    const isMuted = !!settings.muteReputationChangeMessages || !!filters.muteReputationChangeMessages;
    const canNotifyGroup = !isMuted && settings.reputationNotifyInGroup !== false;
    ```
  - Если `canNotifyGroup === false`, баллы пользователю начисляются, событие пишется в историю и системный лог, но ответное сообщение в чат не отправляется.

### Модуль 2. Интеграция суточных итогов репутации в ИИ-суммаризацию дня

#### 2.1. Назначение
Включает в ежедневный ИИ-дайджест блок со статистикой благодарностей и динамикой рейтинга участников за прошедшие 24 часа.

#### 2.2. Требования к реализации
- Настройка: флаг `reputationDailyDigestEnabled: boolean` (по умолчанию `true`).
- Функция генератора HTML-сводки `getDailyReputationSummaryHtml(chatId: string, hoursBack: number = 24)`:
  1. Выбирает из истории репутаций события с временной меткой `>= now - 24 hours` для целевого чата (либо глобальные).
  2. Агрегирует события по пользователям: `netDelta = sum(delta)`, количество благодарностей (`posCount`) и снижений (`negCount`), список причин (`reasons`).
  3. Если событий нет — возвращает пустую строку (блок не рендерится).
  4. Формирует разметку со спойлером:
     ```html
     ⭐️ <b>Итоги изменения репутации за день</b>
     <blockquote expandable>
     За прошедшие 24ч зафиксировано изменений репутации: <b>{total}</b> (благодарностей: <b>+{pos}</b>, снижений: <b>-{neg}</b>).

     🏆 <b>Активность и динамика участников:</b>
     • <b>{Имя}</b> (@username): <b>+{delta}</b> ⭐️ (рейтинг: <code>+{score}</code>)
       <i>Причина: {причины}</i>
     </blockquote>
     ```
  5. Встраивает сформированный HTML в конец суточного дайджеста перед отправкой в Telegram.

### Модуль 3. Начисление репутации по нативным реакциям Telegram (`message_reaction`)

#### 3.1. Назначение
Автоматический учет реакций участников на сообщения (эмодзи) для начисления или списания кармы.

#### 3.2. Требования к реализации
- Подписка на обновление `message_reaction` в `allowed_updates` бота:
  ```typescript
  bot.on('message_reaction', async (ctx) => { ... });
  ```
- Определение автора исходного сообщения:
  - Использовать двухуровневый кэш: быстрая память `messageAuthorCache: Map<string, AuthorInfo>` (ключ `${chatId}_${messageId}`) с фолбэком на коллекцию `chat_messages` в БД.
- Логика реакций:
  - Положительный набор: `['👍', '❤️', '🔥', '👏', '🎉', '🥰', '⚡️']` -> дельта `+1`.
  - Отрицательный набор: `['👎', '🤡', '💩', '🤮']` -> дельта `-1`.
  - Сравнение `old_reaction` и `new_reaction`:
    - Добавление положительной: `+1`
    - Снятие положительной: `-1`
    - Добавление отрицательной: `-1`
    - Снятие отрицательной: `+1`
- Защита от злоупотреблений:
  - Запрет самореакций (`reactor.id === author.userId`).
  - Игнорирование реакций от ботов.

### Модуль 4. Защита Telegram API от 429 Too Many Requests при настройке меню

#### 4.1. Назначение
Предотвращает блокировку и ошибки 429 (Too Many Requests) от Telegram API при частых перезапусках приложения или смене конфигурации кнопки меню (`setChatMenuButton`).

#### 4.2. Требования к реализации
- Кэширование последнего примененного URL:
  - Хранить `lastSetMenuButtonUrl: string | null` в памяти и в документе настроек БД.
  - Если целевой URL совпадает с `lastSetMenuButtonUrl`, вызов `setChatMenuButton` не выполняется.
- Обработка ошибки 429:
  - При возникновении исключения парсить параметр `retry_after`:
    ```typescript
    const waitSec = err.parameters?.retry_after 
      || parseInt(String(err).match(/retry after (\d+)/i)?.[1] || '300', 10);
    menuButtonRetryAfterUntil = Date.now() + (waitSec * 1000);
    ```
  - Персистить `menuButtonRetryAfterUntil` в БД.
  - При последующих вызовах проверять `if (Date.now() < menuButtonRetryAfterUntil) return;` и пропускать вызовы до истечения кулдауна.

### Модуль 5. Предотвращение параллельных запусков и гонок Telegraf (`isInitializingBot` & 409 Conflict)

#### 5.1. Назначение
Исключает коллизии параллельных экземпляров polling одного токена (ошибка 409 Conflict) и зацикливание watchdog-таймеров.

#### 5.2. Требования к реализации
- Мьютекс инициализации:
  ```typescript
  let isInitializingBot = false;
  async function initBot(token: string) {
    if (isInitializingBot) return;
    isInitializingBot = true;
    try {
      // остановка старого polling, очистка webhook, создание Telegraf, запуск
    } finally {
      isInitializingBot = false;
    }
  }
  ```
- Обработка 409 Conflict при `bot.launch()`:
  - Если получен 409 Conflict, устанавливать таймер мягкого повторного запуска с задержкой **30 секунд** вместо агрессивного мгновенного реконнекта.
- Watchdog-таймер:
  - Запускать проверку раз в 60 секунд.
  - Вызывать `initBot` только если:
    `!bot || (!isBotPollingActive && !isInitializingBot && !botReconnectTimer)`.

### Модуль 6. Изоляция сетевых WebSocket-ошибок Vite ModuleRunner в iframe

#### 6.1. Назначение
Предотвращает падение тестов и UI-краши из-за недоступности HMR WebSocket-соединений в изолированных средах (Docker, Cloud Run, Webview).

#### 6.2. Требования к реализации
- Конфигурация Vite:
  - `vite.config.ts`: `server: { hmr: false }`
  - `server.ts` (при dev middleware): `createViteServer({ server: { middlewareMode: true, hmr: false }, appType: 'spa' })`
- Фронтенд-перехватчик в `index.html`:
  - В тег `<head>` перед загрузкой любых бандлов внедрить слушатель событий:
    ```javascript
    window.addEventListener('error', function(e) {
      const msg = (e.message || '') + ' ' + (e.filename || '');
      if (msg.includes('@vite/client') || msg.includes('WebSocket') || msg.includes('createWebSocketModuleRunnerTransport')) {
        e.preventDefault();
        e.stopImmediatePropagation();
        return true;
      }
    }, true);
    window.addEventListener('unhandledrejection', function(e) {
      const str = String(e.reason?.stack || e.reason?.message || e.reason || '');
      if (str.includes('@vite/client') || str.includes('WebSocket') || str.includes('createWebSocketModuleRunnerTransport')) {
        e.preventDefault();
        e.stopImmediatePropagation();
      }
    }, true);
    ```

### Модуль 7. Порог активности для генерации ИИ-дайджестов (Activity Threshold Guard)

#### 7.1. Назначение
Экономия токенов нейросети и предотвращение отправки бессмысленных или пустых сообщений в неактивные чаты.

#### 7.2. Требования к реализации
- Параметр: `minMessagesForDigest: number` (по умолчанию `10` сообщений за 24 часа).
- Логика проверки:
  - Перед отправкой запроса в Gemini/LLM подсчитать количество реальных пользовательских сообщений в чате за отчетный период:
    ```typescript
    if (chatMessagesCount < minMessagesForDigest) {
      addLog({
        type: 'DIGEST',
        details: `ℹ️ [Пропуск по порогу активности] В чате за последние 24ч зафиксировано только ${chatMessagesCount} сообщ. (требуется минимум ${minMessagesForDigest}).`
      });
      return { skipped: true, reason: 'LOW_ACTIVITY' };
    }
    ```

### Модуль 8. Модуль интеграции с MotoBlackList в тело дайджеста

#### 8.1. Назначение
Повышение безопасности участников сообщества путем публикации предупреждений о свежих записях в черном списке продавцов мототехники.

#### 8.2. Требования к реализации
- Парсер/API канала @MotoBlackList: сбор последних постов за последние 24–48 часов.
- Интеграция в форматтер дайджеста:
  - Если обнаружен новый пост и он еще не упоминался в текущем дайджесте:
    ```html
    🚨 <b>Сводка MotoBlackList (Черный список продавцов)</b>
    <blockquote expandable>
    ⚠️ <a href="{post.url}"><b>Публикация #{post.id}</b></a>: «{post.text_preview}»
    👉 <a href="{post.url}">Открыть и прочитать на канале MotoBlackList</a>
    </blockquote>
    ```

### Модуль 9. Строгое HTML-форматирование, скрытые цитаты и обезличенность ИИ-суммаризации

#### 9.1. Назначение
Единый визуальный стиль Telegram-сообщений, исключение юридических рисков и межличностных конфликтов.

#### 9.2. Требования к реализации
- Системный промпт ИИ:
  - Требование строгого синтаксиса: заголовок секции + весь содержательный блок под `<blockquote expandable>`.
  - Требование **полной обезличенности** в анализе атмосферы и настроения чата (запрет тегов `@username`, имен и персональных оценок конкретных людей).
- Пост-обработка и сплиттер длинных сообщений:
  - Лимит одного сообщения Telegram — 4096 символов (безопасный порог сплиттера: 4000).
  - При превышении лимита делить сообщение по границам абзацев, сохраняя валидность открытых/закрытых HTML-тегов (`<b>`, `<blockquote>`, `<code>`).
  - Фолбэк-механизм: если Telegram отклоняет сообщение с ошибкой парсинга HTML, повторить отправку со стриппингом неподдерживаемых тегов, а при повторной ошибке — отправить в plain text.

### Модуль 10. Публичный каталог чатов и генерация XML-экспорта (`/export.xml`)

#### 10.1. Назначение
Предоставление публичного каталога сообществ и автоматическая выгрузка детального XML-файла со статистикой активности и архивом дайджестов за 30 дней.

#### 10.2. Требования к реализации
- Модуль `xmlExport.ts`:
  - Структура XML:
    ```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <mototg_export generated_at="ISO_DATE" total_chats="N">
      <metadata>...</metadata>
      <chats>
        <chat id="ID" slug="SLUG" username="NAME">
          <title><![CDATA[...]]></title>
          <members_count>...</members_count>
          <messages_24h>...</messages_24h>
          <digests>
            <digest id="ID" date="YYYY-MM-DD">
              <html_text><![CDATA[...]]></html_text>
            </digest>
          </digests>
        </chat>
      </chats>
    </mototg_export>
    ```
- Кэширование:
  - Генерация файла в `public/export.xml` по расписанию раз в сутки или по требованию через cron.
  - Кэширование XML-строки в памяти сервера для мгновенного ответа на GET-запросы без повторной сборки.
- Эндпоинты:
  - `GET /export.xml` — отдача XML с `Content-Type: application/xml`.
  - `GET /api/public/chats-catalog` — JSON-версия каталога для веб-витрины.
